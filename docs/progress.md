# Project progress — 0.3.0-rc20 WIP

RC20 is the active Minecraft 1.12.2 release-candidate work tree. It retains the verified RC19 Kotlin/liquid-acoustics baseline and now adds transactional custom-shader-pack reload, bounded entity-derived projectile flight emitters, a probe-only direct-path diagnostic, universal Forge-fluid discovery/identity overrides, and a stronger explosion/projectile x AIR/WATER/LAVA matrix. The projectile flight emitter now also owns a real client-side Forge `RegistryEvent.Register<SoundEvent>` registration for `acousticshaders:projectile.flight`; the legacy regression deliberately removes that registration first and requires the emitter to fail closed, preventing `sounds.json` alone from masquerading as a registered event. The current tree passes 54 headless + 39 advanced tests and the full Forge/Mixin/Paulscode legacy contract. The historical RC19 exact-Kotlin 2.4.0 deterministic artifacts remain valid evidence for that frozen baseline only; they are not automatically inherited by RC20. RC20 still requires a clean exact-Kotlin 2.4.0 unified verification/package run. The official real-SRG gate and the new EntityTippedArrow/TNT-liquid probes are wired into `dev-verify.sh`, but in this container their RC20 execution is blocked until the exact MCPConfig `1.12.2-20200226.224830` bytes are present. The RFG-equivalent audit no longer trusts a fixed historical class count: it compares the JAR with the exact verified production class set. Physical NVIDIA CUDA-FDTD, physical audible/perceptual output, and broader modpack compatibility remain external hardware/integration boundaries.

## RC9/RC10 real-client performance findings addressed

The RC8 report from a hybrid Intel UHD 620 + NVIDIA MX130 notebook confirmed that the OpenCL probe/selector chose the Intel iGPU; RC8 did not yet export trace/self-test counters and showed two integrated-server overload events (2.624 s and 2.164 s behind). Source solve latency had a low median but long tails up to ~344 ms, while periodic full scene refreshes sampled 28,749 voxels on the client thread. RC9/RC10 added cross-vendor/discrete-aware OpenCL selection diagnostics, time-sliced full-volume validation, acoustic-content revision stability, lower automatic worker pressure on 4-thread CPUs, and slow-pass timing logs. RC11 adds CUDA as an independent higher-priority accelerator rather than changing that CPU/frame-pacing policy.

## RC10 real-client cave-EFX finding

The RC9 report confirmed NVIDIA GeForce MX130 OpenCL ray execution (`self-test=pass`, zero failures). HIGH still uses the modal wave solver, so the FDTD OpenCL backend was available but had zero solves. In the enclosed cave segment the listener-room estimate reached roughly openness 0.034, RT60 1.71 s and mean free path 5.56 m. Mapping that mean path literally onto the legacy EFX single early-reflection/late-delay controls produced a plausible but perceptually too discrete second onset. RC10 keeps the full hybrid/RIR physics unchanged, but makes the lossy EFX fallback deliberately more diffuse: lower single-cluster reflection gain, much shorter reflection/late onset, and acoustic-signature hysteresis so near-identical scene revisions do not reset the shared reverb state.
